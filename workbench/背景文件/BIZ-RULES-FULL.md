# 第一部分：人和部门

## 1.1 四类人

| 角色 | 系统里的叫法 | 干什么 |
| --- | --- | --- |
| **部长** | `minister` | 派活、审核、核定工时。只管自己部门 |
| **干事** | `member` | 接活、干活、交成果、给自己登记工时 |
| **外部用户** | `兄弟部门` 账号 | 提需求、报名。**不算工时，但要留记录** |
| **指导老师** | `admin` | 看全部、可代任何环节、改规则。**不参与日常审核**（二审由部长代职） |

> ⚠️ **口径要统一**：采访稿说「外部用户」是"其他需要青传辅助工作的人"（泛指个人），现在系统里只有「兄弟部门」这一类账号（其他学生组织）。到底是只服务其他学生组织，还是任何外部个人都能提需求？

## 1.2 六个部门

| 部门 | 干什么 |
| --- | --- |
| **办公部** | ① 挂网（稿件来源：采编部、外部用户）② 津贴统计（全中心最痛的点） |
| **采编部** | 写稿 → 部长审核 → 交办公部挂网 → 交运营部做推文 |
| **运营部** | ① 外部稿件转发 ② 自己写稿做推文 ③ 部长负责推文一审 |
| **摄制部** | 承接拍摄需求。**要派发 + 抢单两条通道，抢单先到先得** |
| **美编部** | 接各部门、各类人员的绘画/配图需求 |
| **原创部** | 职能接近运营部，但更自由 |

> ⚠️ 采访稿 B 段把「原创部」写成了「后勤部」，同一段描述出现两个名字。以「原创部」为准（部门表里没有后勤部）。

## 1.3 谁能管谁

| 角色 | 能管的人 |
| --- | --- |
| 部长 | 只有**自己部门** |
| 干事 | 只有**自己** |
| 管理员 | 全部 |
| 外部用户 | 只能管自己提的需求 |

# 第二部分：六条业务流程

## 2.1 采编挂网（采编 → 办公 → 运营）

> 这是全中心唯一已经跑通自动化算钱的流程。也是津贴统计的样板。

### 谁能发起
只有**采编部**的人或管理员。

### 要填什么
| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 标题 | 是 | 这次协同的标题 |
| 稿件清单 | 是 | **一篇稿子一行**，每行写清稿子名称 + 投哪个网站 |
| 目标网站 | 否 | 不填默认「院网、升华网、学工网」 |
| 稿件类型 | 是 | **原创** / 转载。决定给不给写稿人算钱 |
| 审核人 | 是 | 可以多个 |
| 截止日期 | 否 | |
| 提前多少小时提醒 | 否 | |
| 备注、附件 | 否 | |

> **稿件清单的写法**（用户原话举例）：
> ```
> xx文档，升华网投稿；
> xx文档，学工网投稿
> ```
> 这样写 = **两条稿件记录**，各自算一次工时。

### 流转
1. 采编提交 → 状态「待派发」，通知办公部部长。
2. 办公部部长派给本部门干事。
3. 干事交活：写「同步结果」或传截图，二选一必填。
4. 审核：采编部部长 / 办公部部长 / 管理员。
5. 通过 → 归档 + 自动算钱。
6. 退回 → **退回给原承接人重做，不能换人**。

### 算多少钱

| 谁 | 算什么 | 多少 | 记录粒度 |
| --- | --- | --- | --- |
| 写稿人（**仅原创**） | 新闻稿创作 | **5 小时 × 篇数** | **一篇一条记录** |
| 办公部对接干事 | 采编办公对接 | **4 小时 × 篇数** | **一篇一条记录** |
| 审核人 | 新闻稿审核 | **共 2 小时，多人平分** | 一单一条记录 |

> ⚠️ **待确认**：采访稿说采编的稿子挂网后还要"交运营部做推文"。现在系统里流程到办公部归档就结束了，**没有推文这一步**。是漏了，还是推文走别的流程？

## 2.2 摄制拍摄

### 谁能发起
**任何部门的人**都能发起，包括外部用户。

### 要填什么
| 字段 | 必填 |
| --- | --- |
| 任务名称 | 是 |
| 预约时间（必须晚于现在） | 是 |
| 地点 | 是 |
| 联系方式 | 是 |
| 备注、附件 | 否 |

### 加急判定（第一套标准）
> **预约时间 − 现在 < 2 天 → 自动标加急**

- 门槛 2 天、倍数 1.5 倍，管理员可改。
- 加急倍数**乘在工时上**，不乘时薪。
- ⚠️ 采访稿还要求「加急**需说明**」，现在没有"说明原因"这一栏。要不要加？

### 流转
1. 提交 → 状态「待派发」，通知摄制部部长。
2. **两条接活通道**：
   - **派发**：部长指定干事（现在已实现）
   - **抢单**：干事自己抢，先到先得（**现在没实现**）
3. 干事交活：写完成说明、传成品。
4. **部长审核通过 → 自动归档**，不需要办公部归档人。
5. 退回 → 退回给原承接人重做，不能换人。

### 算多少钱

| 谁 | 多少 |
| --- | --- |
| 摄制干事 | **4 小时 × 加急倍数** |
| 审核的摄制部部长 | **2 小时** |

> **2026-11-06 定**：原来那 2 小时是给办公部归档人的，现在改给摄制部审核部长。摄制流程里**不再有办公部的人**。
>
> ⚠️ **待确认**：这 2 小时是"每个摄制任务都有"，还是"只有加急任务才有"？

## 2.3 公众号排版

### 两种发起方式

**A. 运营部自己建任务**
- 运营部部长或管理员建。
- 必须同时指定：干事、一审人、二审人（都必须是运营部的）。

**B. 外部用户发需求**
- 外部用户只填：标题、排版类型、截止日期、备注、附件。
- 状态「待运营部接单」，通知运营部部长。
- 运营部部长接单时指定：干事 + 一审 + 二审。

### 排版类型决定工时
| 类型 | 干事工时 |
| --- | --- |
| 基础排版 | 4 小时 |
| 影像志排版 | 2 小时 |
| 内容转载排版 | 1 小时 |

### 加急判定（第二套标准）
> **外部用户距截止不足 2 天时报名 → 标加急**

- 这套跟摄制那套**不是同一个规则**，各自独立。
- **2026-11-06 定**：排版加急**也要 ×1.5**。原来文档型数据库做不了，换 PG 后要补上。

### 外部用户可以报名
- 只有外部用户能报名。
- 一个人不能重复报名。
- **报名不产生工时，但留一条报名记录**（谁、什么时候、交了什么附件）。
- 距截止不足 2 天报名 → 标加急 + 提醒排版干事。

### 两级审核
- 一审通过 → 状态「待二审」。
- 二审通过 → 归档 + 算钱。
- **一审二审是同一个人的话，一审通过就直接归档**，不用审两次。
- 二审要记录**是哪位部长**审的。

### 算多少钱

| 谁 | 多少 |
| --- | --- |
| 排版干事 | 按类型 4 / 2 / 1 小时 × 加急倍数 |
| 审核人 | **共 2 小时，两人平分** |

## 2.4 外部需求（别的组织找我们帮忙）

### 谁能发起
**只有外部用户或管理员**。

### 能找哪些部门
办公部、采编部、美编部、摄制部、运营部、原创部（六选一）。

> 采访稿只说了三个方向（运营转发推文、摄制拍摄、办公供稿挂网），实际支持六个部门。以六个为准。

### 要填什么
标题、目标部门、截止日期、备注、附件。

### 流转
1. 提交 → 目标部门部长收到通知。
2. 部长派给本部门干事。
3. 干事交活 → 部长审核 → 归档。

### 算多少钱

| 谁 | 多少 |
| --- | --- |
| 承接干事 | 按**目标部门的创作者规则**（见第四部分） |
| 审核部长 | **固定 2 小时**，且必须在目标部门有成员档案 |
| 发起人（外部用户） | **不算工时，但留一条需求记录** |

> **2026-11-06 定**：管理员可以点审核按钮（方便测试），但**管理员审不给工时**。

## 2.6 工作登记（没有流程的活）

### 谁能登记
- 干事：只能给自己。
- 部长：只能给本部门的人。
- 管理员：任何部门。

### 要填什么
周次、工作内容、工时、工作类型、备注、附件。

### 关键规则
- **一件事 = 一条记录**。干 5 件事就是 5 条，不合并成一条大文本框。
- **有规则可套的，工时按规则自动带出**（比如"新闻稿创作"带出 5 小时）。
- **没规则可套的（选"其他"），工时必须手填**，并标记为"人工填报"。
- 工时不允许留空、不允许填 0 或负数。

> 2026-11-06 定：这条是从文档型数据库换到 PG 的核心原因之一。

# 第五部分：钱怎么算

## 5.1 基本公式
```
金额（分） = 四舍五入(工时 × 时薪)
```
- 工时用「万分之一小时」为最小单位存，避免小数误差。
- 时薪 **10 元 = 1000 分**。

## 5.2 加急
- **两套独立标准，不共用**：
  - 摄制：按「预约时间 − 现在 < 2 天」判定
  - 排版：按「外部用户距截止 < 2 天报名」判定
- 倍数 **1.5**，**只乘工时，不乘时薪**。
- 门槛和倍数管理员可改。

> ⚠️ **待确认**：摄制时薪 12 元这个设置项，用户说"不删保留"。那实际算钱时，摄制是按 10 元还是 12 元？

## 5.3 谁能改工时

| 角色 | 能不能改 |
| --- | --- |
| 干事 | **不能改已归档的** |
| 部长 | **能改本部门任何人的工时**，包括系统自动算的 |
| 管理员 | 能改全部 |

- 改的时候要留痕：谁改的、改前多少、改后多少、为什么改。
- **期末才结算**，周报是过程数据，改了会跟着变。

## 5.4 不能改的东西
- 审核类规则的 2 小时（固定）
- 已封存的周报（历史快照）

# 第六部分：状态

## 6.1 七种状态
| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 待派发 | 已提交，等部长派人 | 派发 |
| 已派发 | 有人接了，等交活 | 交活 |
| 已交活 | 等审核 | 审核 |
| 一审通过 | 排版专用，等二审 | 二审 |
| 已退回 | 打回去了，等重做 | 重新交活 |
| 已归档 | 完事了，钱已算 | — |
| （取消） | 成员资料对不上时强制关单 | — |

## 6.2 状态不是存出来的
> 状态由「谁做了什么」推导出来，不是数据库里存一个字段。这样不会出现"已归档但没有归档记录"这种脏状态。

## 6.3 退回
- 退回必须写原因。
- **退回后只能原承接人重做，不能换人**。
- 重做后重新走审核。

# 第七部分：提醒

- 每单可以设「提前多少小时提醒」。
- 到期前提醒一次，过期后提醒一次，各只发一次。
- 发给**当前该处理的人**：
  - 待派发 → 承接部门部长
  - 已派发 → 承接干事
  - 待审核 → 审核人
