# Feature Specification: 角色工作台与分组导航

**Feature Branch**: 无 Git 仓库；006-role-workspace
**Created**: 2026-11-26
**Status**: Ready
**Input**: 用户认可角色工作台草案，要求按“角色工作台为主、业务快捷入口为辅”改好并展示实际网页。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 找到与自己有关的工作 (Priority: P1)
干事、部长、老师、办公部和需求方按实际身份看到分组入口和不同的工作概览。
**Why this priority**: 解决入口平铺、重点不明，支持每天登录直接开始工作。
**Independent Test**: 五类身份分别登录，核对入口、首页重点和跳转；桌面与手机均能操作。
**Acceptance Scenarios**:
1. **Given** 干事登录，**When** 查看个人工作，**Then** 可进入我的待办、我发起的和消息中心；不显示部门管理。
2. **Given** 部长登录，**When** 查看首页，**Then** 可进入部门任务、审核工作台和待核定工时。
3. **Given** 老师登录，**When** 查看首页，**Then** 优先展示轮到本人的稿件，不展示工时入口或统计。
4. **Given** 需求方登录，**When** 查看首页，**Then** 展示自己的需求进度和待补材料，开放报名不混入本人待办。

### User Story 2 - 从待办直接进入下一步 (Priority: P1)
用户在独立任务视图中区分本人待办、本人发起、部门协作及审核，按优先级进入实际详情处理。
**Why this priority**: 将任务中心内隐藏的日常工作提出来，避免重复翻找。
**Independent Test**: 创建跨角色流转任务，核对派发、交稿、退回、一审、二审、发布和归档后待办同步变化。
**Acceptance Scenarios**:
1. **Given** 推文处于一审，**When** 两位老师分别登录，**Then** 只有一审老师在待审列表看到该任务；一审通过后转为二审老师待办。
2. **Given** 同部门干事查看任务，**When** 切到我的待办，**Then** 他人承接的任务不出现。
3. **Given** 用户已处理过审核，**When** 查看已审记录，**Then** 仍可找到关联任务并查看实际审核历史。
4. **Given** 空列表、加载中或请求失败，**When** 查看页面，**Then** 分别显示明确状态，不把加载或失败伪装成零条任务。

### User Story 3 - 按业务快速进入协作 (Priority: P2)
首页提供公众号、采编、摄制、美编、部门需求、工作登记的入口，进入统一任务视图，允许列表/看板和业务筛选。
**Why this priority**: 提高业务可发现性，复用统一归档与权限。
**Independent Test**: 点击每种业务，核对业务筛选及适用的新建表单，刷新后保留当前业务。
**Acceptance Scenarios**:
1. **Given** 选择摄制预约，**When** 打开任务中心，**Then** 只列出当前可见的摄制任务；有发起权限时新建直接选摄制。
2. **Given** 无该业务发起权限，**When** 查看任务，**Then** 仍按可见权限展示，隐藏不适用的创建入口。
3. **Given** 切换看板，**When** 打开卡片，**Then** 进入同一任务详情，显示当前环节和下一步，无重复数据。

### Edge Cases
- 老师/外部账号访问工时报表或管理页面，显示无权访问与返回入口。
- 归档、工作登记不进入待办；强制归档继续明确工时未自动核算。
- 一审与二审须不同老师；两位部长任一确认后双方待内审数量同步减少。
- 办公部普通干事仍是普通干事；全中心统计仅办公部长/管理员可用。
- 没有截止时间显示未设截止；已过期与两日内到期分开标识。
- 手机菜单可关闭、按 Escape 关闭并恢复焦点；长标题和多业务不撑破页面。
- 消息尚无已读机制，本次不虚构未读数量；列表最多现有接口返回的 500 项，页面标明范围。

## Requirements *(mandatory)*

### Functional Requirements
- **FR-001**: 导航按个人工作、任务协作、成果与统计、部门管理分组，根据身份隐藏不适用入口。
- **FR-002**: 各身份首页显示相关工作重点、真实数量和可点击的优先处理队列。
- **FR-003**: 我的待办只包含当前轮到本人执行的任务，下一步标明供稿、派发、交付、审核、发布等实际动作。
- **FR-004**: 我发起的、部门任务、审核工作台具有独立入口；已审列表来自实际审核记录。
- **FR-005**: 首页业务入口进入已筛选的任务视图；适用的新建表单预选该业务。
- **FR-006**: 任务中心支持列表与按环节分组的看板；任务标题、状态、截止、处理人、下一步可见。
- **FR-007**: 首页工时与核定数量来自实际工时记录；教师、外部用户不请求或展示工时；部长核定入口默认本部待核定。
- **FR-008**: 保留原有详情、报表、通知、设置路由；限制页面直达且业务操作继续由服务端鉴权。
- **FR-009**: 支持 320、390、768、1024、1440 像素宽度，菜单及新增控件支持键盘，有加载、错误、空状态。
- **FR-010**: 不改变计价、归档或微信接入规则；验证五类角色隔离、完整业务回归与实际页面截图。

### Key Entities
- 任务工作上下文：任务当前环节、本人与任务关系、待执行动作和实际审核经历。
- 工作区视图：角色允许的入口、所选业务、列表或看板。
- 工作台摘要：在当前可见任务范围内的队列计数，以及按既有权限可见的工时记录。

## Success Criteria *(mandatory)*

### Measurable Outcomes
- **SC-001**: 五类身份均可在首页一次点击进入其主要工作队列，两次点击内打开任务详情。
- **SC-002**: 公众号跨角色验收中每次流转后的待办人员与当前环节一致；无关干事与另一审老师误列数为 0。
- **SC-003**: 六类业务均可从首页进入已筛选视图；列表、看板与业务刷新后范围一致。
- **SC-004**: 五个验收宽度无页面横向溢出，新增导航和筛选不出现脚本错误。
- **SC-005**: 老师与外部身份的页面、请求均无工时数据，已有归档计时与报表回归通过。

## Assumptions
- 沿用既有账号、六部门、真实业务和服务端权限，不新增组织角色。
- 当前身份由登录会话决定，实际产品没有预览草图中的任意切换身份控件。
- 未接通的微信服务仍明确标识；云托管连通问题不在本次工作区改造范围。
- 本次验证包括浏览器集成与角色流转检查，使用隔离测试数据。
