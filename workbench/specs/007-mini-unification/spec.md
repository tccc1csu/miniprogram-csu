# Feature Specification: 两端统一与小程序重构

**Feature Branch**: `feat/unified-cloud-workbench`
**Created**: 2026-11-26
**Status**: Ready
**Input**: 小程序按现有网页业务重构；两端共用云端数据；保留旧环境；统一提交到 miniprogram-csu。

## User Scenarios & Testing

### User Story 1 - 同一账号与工作台 (Priority: P1)
成员、部长、老师和外部组织使用网页现有账号登录小程序，按身份看到待办、任务、消息和个人信息。保留原有蓝色卡片式移动布局及“首页／协作广场／我的”三个底栏，删除独立“新版工作台”入口，原页面直接替换为统一业务。
**Why this priority**: 消除两套身份及数据孤岛。
**Independent Test**: 使用四类账号分别登录，对照网页可见任务；退出后不得看到上一个账号的数据。
**Acceptance Scenarios**:
1. Given 已有网页账号，When 小程序登录，Then 姓名、身份、任务一致。
2. Given 会话失效，When 刷新，Then 返回登录并清空账号相关页面数据。

### User Story 2 - 移动办理与自动归档 (Priority: P1)
按权限发起六类业务、交供稿、上传材料、安排承接、提交成果、审校、验收、发布、查看历史及备注。
**Why this priority**: 移动端能完成日常工作，继续沿用既有规则。
**Independent Test**: 小程序发起外部推文，采编审核后安排、交稿、内审、不同老师两审、发布；网页看到同一归档和工时。
**Acceptance Scenarios**:
1. Given 外部推文，When 提交供稿，Then 先到采编，不能跳入排版。
2. Given 指定老师，When 审核当前版本，Then 只推进该老师的环节，老师无工时。
3. Given 任务正常完成或强制关闭，When 查看归档，Then 正常任务仅一次计时，强制关闭零自动工时。
4. Given 任意六部门任务，When 保存任务备注，Then 网页及导出可见。

### User Story 3 - 进度、材料与个人工时 (Priority: P2)
用户在手机查看进度、版本、批注、消息和本人核定工时；复杂文中划选批注、自由报表、政策配置和期末封存继续在网页办理。
**Why this priority**: 保持移动端易用，同时保留完整记录。
**Independent Test**: 部长个人工时仅包含本人；教师、外部不显示工时；私有附件越权失败。
**Acceptance Scenarios**:
1. Given 部长登录，When 打开个人工时，Then 不把部门总工时显示成本人工时。
2. Given 微信机器人未配置，When 打开消息，Then 仅标识站内事件，不伪称微信送达。

### User Story 4 - 可维护交付与云端运行 (Priority: P1)
同一仓库包含两端、后端、规格、测试及部署说明，保留历史及旧环境，关闭本机仍能办理。
**Why this priority**: 提供可维护、可回退的大版本。
**Independent Test**: 检查仓库完整性、敏感文件排除、云端账号和材料联调。
**Acceptance Scenarios**:
1. Given 旧生产环境和本地未提交改动，When 发布新版代码，Then 旧数据库不被写入/删除且本地原文件有备份。
2. Given 本机后端停用，When 小程序调用云端，Then 登录、任务和材料正常。

### Edge Cases
断网保留表单且不自动重试写操作；超时提示刷新核对，避免重复创建；过期会话清空视图；外部公开报名显示最小字段；过期报名由服务端拒绝；文件过大提示改用网页；新版本导致旧审校提交冲突时刷新详情。

## Requirements
### Functional Requirements
- **FR-001**: 共用既有账号和服务端角色，不接受手机自报权限。
- **FR-002**: 工作台按身份显示本人待办，支持全部、待办、发起、归档与搜索。
- **FR-003**: 六类业务按既有权限提供入口与必填字段，不允许跳过源稿审核或老师两审。
- **FR-004**: 当前版本办理安排、交付、审核、发布、强制关闭及任务备注；默认承接和审校组合可选。
- **FR-005**: 正常完成自动归档与一次计时；教师/外部不计时，强制关闭不自动计时。
- **FR-006**: 私有材料上传/下载携带身份，展示失败、大小限制及补交入口。
- **FR-007**: 查看版本、审校、批注和时间线；移动整体审校，精细原文批注提供网页入口。
- **FR-008**: 仅内部展示个人工时，按本人过滤，展示规则值、核定值、备注及金额。
- **FR-009**: 站内消息按本人可见，未接微信订阅或机器人时如实标识。
- **FR-010**: 核心数据不写旧文档库，不删除旧环境；新增转发能力不改原有云函数。
- **FR-011**: 同仓库完整交付两端与后端、部署文档和验证，不提交密钥、运行数据或本地个人配置。
- **FR-012**: 云端运行不依赖本机进程；保留后续切换接入环境的集中配置。

### Key Entities
用户会话；任务与当前版本；审核及批注；材料；归档与工时；站内通知。沿用现有业务实体，不复制两套数据。

## Success Criteria
### Measurable Outcomes
- **SC-001**: 21 个既有验收身份继续可用，四类角色首页和任务权限正确。
- **SC-002**: 六类业务均可从有权身份发起并查看；至少一条跨端完整闭环及私有附件联调成功。
- **SC-003**: 本机服务停止时云端登录、任务列表和附件仍成功；非法会话和越权访问被拒绝。
- **SC-004**: GitHub 中两端代码、规格和运行说明可定位，旧数据库零写入/零删除。

## Assumptions
- 既有网页业务规则和 47 个验收场景继续作为参照。
- 不在本次自动发布微信正式版；编译、预览和云端接口验证与微信审核发布分开记录。
- 保留旧环境作为接入适配及回退；旧业务数据仅参考，不做生产迁移。
