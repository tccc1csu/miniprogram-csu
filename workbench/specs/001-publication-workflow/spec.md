# Feature Specification: 供稿发布、自动归档与工时工作台

**Feature Branch**: 无，规格目录独立于分支
**Created**: 2026-11-22
**Status**: Ready for planning
**Input**: 实现用户确认的首条闭环；其他全量业务见 ../002-center-workflows/spec.md 和 ../business-coverage.md。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 供稿与排版协作 (Priority: P1)
兄弟组织提交排版需求，运营部长派人，干事提交包含正文、预览及素材的不可变版本；运营部长也能直接自建任务。
**Why this priority**: 形成统一任务入口，替代群里分散的交接。
**Independent Test**: 外部账号创建任务、部长指派、干事提交，双方看到同一编号。
**Acceptance Scenarios**:
1. **Given** 已登录外部账号，**When** 提交标题、排版类型、截止日和材料，**Then** 只生成一条需求且发起人能查。
2. **Given** 待接单任务，**When** 运营部长指派本部干事，**Then** 无关部门不能指派，该干事获得待办。
3. **Given** 干事已提交版本，**When** 重新交修改稿，**Then** 保留原稿和意见，旧版通过不能授权新稿。

### User Story 2 - 内审与老师两审 (Priority: P1)
每篇固定两名运营部长为审校人员，任一确认可送老师；一审二审均由教师独立操作。
**Why this priority**: 真实反映组织审校和责任时间线。
**Independent Test**: 一个部长确认、教师两次通过进入待发布。
**Acceptance Scenarios**:
1. **Given** 本篇已配置两位有效运营部长，**When** 一位确认，**Then** 当前版进入老师一审并记操作人。
2. **Given** 任一审查退回，**When** 未写理由，**Then** 拒绝；重新提交后从内审开始。
3. **Given** 教师一审通过，**When** 同一老师进行二审，**Then** 仍须单独通过记录；不得自动跳过。

### User Story 3 - 发布自动归档计时 (Priority: P1)
二审通过后，实际发布者填正式链接确认；系统保存成果、版本与审校历史并自动生成工时。
**Why this priority**: 自动归档和学期计钱是核心目标。
**Independent Test**: 完成一个基础排版任务后有一个档案、干事4h、两位固定部长各1h，教师与外部账号无工时。
**Acceptance Scenarios**:
1. **Given** 仅二审通过，**When** 尚未确认发布，**Then** 不生成已发布档案和工时。
2. **Given** 有最终正文或持久附件、合法正式链接，**When** 确认发布，**Then** 同事务归档、生成工时和通知出站记录。
3. **Given** 发布请求重试，**When** 连续或并发提交，**Then** 档案和工时均不重复。
4. **Given** 附件只能由授权者查看，**When** 无关外部账号猜测下载地址，**Then** 拒绝。

### User Story 4 - 核定与灵活报表 (Priority: P2)
个人查来源，部长核定和调整，办公部跨部门对账，按周或日期与学期视图导出并封存。
**Why this priority**: 工时账与期末结算保持同一口径。
**Independent Test**: 调整一个条目并导出，合计正确，封存后新调整不改变旧快照。
**Acceptance Scenarios**:
1. **Given** 本部条目，**When** 部长输入正数核定工时与理由，**Then** 保存旧值新值和操作者，规则值不变。
2. **Given** 表格，**When** 筛选成员、类型、核定状态、日期范围并排序分组调列，**Then** 保存视图后重开相同，Excel与所见筛选范围一致。
3. **Given** 当前明细，**When** 办公部封存日期区间，**Then** 保存对应行、金额及合计，原始明细后续调整不改历史。
4. **Given** 教师/外部账号，**When** 打开工时账或尝试核定，**Then** 不计发且无法越权操作。

### User Story 5 - 移动需求与开放报名 (Priority: P2)
小程序共用接口，外部用户可对明确开放任务报名并提交附件；一次报名不产生工时。
**Why this priority**: 保留微信中的便捷入口。
**Independent Test**: 同一外部账号重复报名被拒，其他外部任务的私人附件不暴露。
**Acceptance Scenarios**:
1. **Given** 明确开放的任务，**When** 外部账号报名，**Then** 留参与记录，未开放任务不能报名。
2. **Given** 报名距截止小于48小时，**When** 首次报名，**Then** 标记排版加急并通知执行者；截止或已归档后拒绝新报名。

### Edge Cases
- 重复发布、重复报名、并发状态转换、跨部门越权、空退回理由、失效版本。
- 两个审校部长必须不同且有效；离任不影响历史归属，但新任务不能再指派。
- 只存临时预览链接不能作为唯一归档成果；至少存正文或持久附件。
- 严格不足48h标加急；截止后不接新报名；归档后禁止替换最终稿。
- 非完整核定记录不能被误认为最终已核定金额；封存明细包括当时核定状态。

## Requirements *(mandatory)*

### Functional Requirements
- **FR-001**: 提供登录、会话、服务端角色/部门/参与范围检查，教师与管理员分离。
- **FR-002**: 支持运营自建和兄弟组织需求，验证类型、日期、标题、固定两名部长，任务编号唯一。
- **FR-003**: 仅本部门部长或管理员指派同部成员，提交限承接人或有代办权限者。
- **FR-004**: 稿件版本和材料不可覆盖，审批绑定当前版本；修改后内审重走。
- **FR-005**: 任一固定部长内审可过，老师一审二审各留记录；退回理由必填。
- **FR-006**: 二审后由任务执行者或本部部长/管理员填http(s)正式链接确认发布，自动归档与计发原子完成。
- **FR-007**: 基础/影像志/转载按4/2/1h，固定两部长分2h；排版报名加急乘1.5于创作者工时，审校不乘；时薪10元；仅内部成员可计发。
- **FR-008**: 按万分之一小时与金额分保存规则快照；审核基础规则保持2h，允许本部部长有理由地核定例外值。
- **FR-009**: 工时明细来源可查，保存调整历史，区分待核定与已核定。
- **FR-010**: 支持报表筛选、排序、分组、列配置、个人保存视图和Excel导出。
- **FR-011**: 办公部/管理员可创建封存快照并导出；快照不可被后续调整改写。
- **FR-012**: 档案可搜索，呈现最终稿、文件、正式链接、版本审查时间线和贡献明细。
- **FR-013**: 附件有摘要、大小、上传者，下载和关联均校验权限；未接真实云存储时使用本地持久目录。
- **FR-014**: 只对明确开放任务提供外部报名，唯一约束防重复，参与者不计时；服务端判定不足48h加急。
- **FR-015**: 所有变更可追查；通知写入出站表，未接群渠道不得显示发送成功。
- **FR-016**: 提供可运行的小程序需求与进度入口及共用接口说明；正式微信登录绑定依赖AppID和服务端凭据。
- **FR-017**: 使用关系数据库、版本化迁移、约束和事务；状态从动作推导。
- **FR-018**: Web 至少有工作首页、任务、任务详情、档案和工时报表，支持手机浏览。

### Key Entities
账号/部门成员、任务/指派、固定审校人、版本/附件、审核动作、报名、发布、档案、工时、调整、视图、封存明细、通知出站、会话。

## Success Criteria *(mandatory)*

### Measurable Outcomes
- **SC-001**: 本地自动验证一条完整真实数据库闭环，预期4+1+1h、金额60元且无教师/外部工时。
- **SC-002**: 10次重复发布只产生一个档案和三条贡献明细；注入失败不留下部分归档。
- **SC-003**: 覆盖跨部门派发、无关附件读取、旧版审批、非法跳审与报表越权拒绝场景。
- **SC-004**: 封存前后调整对比中，快照逐行与合计均不变；筛选导出与接口明细合计一致。
- **SC-005**: 桌面与手机视口完成浏览及关键操作的浏览器验证，无横向溢出的主要表单。

## Assumptions
- 本地验证使用内嵌PostgreSQL，生产适配真实PostgreSQL；云只读探测已通过，正式应用部署另行验证。
- 开发账号仅用于本地验证；生产禁用初始化演示账号，实际用户登录与微信绑定需独立配置。
- 修改后完整重新审批是默认，不把旧版批准复用到新版。
- 群通知真实发送待群类型和渠道凭据。全业务后续依赖本规格基础，不遗漏。
