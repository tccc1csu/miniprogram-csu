## User Scenarios & Testing *(mandatory)*

### User Story 1 - 采编供稿挂网 (Priority: P1)
采编或管理员建任务，稿名与目标网站逐行录入，默认院网、升华网、学工网；原创/转载、审核人、截止日、附件和提醒设置独立。
**Why this priority**: 基准唯一已跑通核算的样板。
**Independent Test**: 两条稿件明细完成挂网，分别产生创作/对接记录且按篇正确。
**Acceptance Scenarios**:
1. **Given** 已提交，**When** 办公部长派本部干事，**Then** 仅承接人或代办者能交结果说明或截图，至少一项必填。
2. **Given** 待验收，**When** 采编/办公部长或管理员通过，**Then** 自动归档，原创每篇写稿5h、办公每篇4h、内部审核合计2h平分。
3. **Given** 需做公众号，**When** 新建关联排版任务，**Then** 复用素材但不重复算同一贡献；不强制所有挂网稿都做推文。
4. **Given** 内容需老师审核，**When** 进入挂网交付前，**Then** 内容审查与挂网成功验收分开，配置明确，不能把验收代作老师审核。

### User Story 2 - 摄制派发与抢单 (Priority: P1)
任何内部成员或兄弟组织预约，时间须晚于当前，填地点、联系人、备注、附件；部长派发或摄制干事抢单先到先得。
**Why this priority**: 高频跨部协作。
**Independent Test**: 两名干事同时抢仅一人成功；部长验收即归档。
**Acceptance Scenarios**:
1. **Given** 预约距离提交不足48h，**When** 提交，**Then** 加急快照为1.5，恰好48h不加急。
2. **Given** 未指派，**When** 多人抢或部长派发竞态，**Then** 仅一承接人，不能覆盖成功指派。
3. **Given** 交付通过，**When** 摄制部长验收，**Then** 自动归档，干事4h乘加急，审核部长基础2h，不包含办公归档人。
4. **Given** 退回，**When** 重新交付，**Then** 原承接人修改，不擅自换人。

### User Story 3 - 六部需求、美编与原创 (Priority: P2)
外部组织/管理员选六部门之一提需求；目标部派发交付审核。美编内部也能提绘画/配图需求，以基础/复杂/大型区分。
**Why this priority**: 补足旧小程序缺失流程。
**Independent Test**: 美编复杂设计由美编部验收，创作者6h，外部无账。
**Acceptance Scenarios**:
1. **Given** 目标部门任务，**When** 本部部长验收，**Then** 自动归档并按选定创作规则计时，审核部长固定基础2h且须有本部档案。
2. **Given** 美编任务，**When** 基础/复杂/大型完成，**Then** 分别3/6/9h，基础或大型审核用已有2h规则；复杂审核暂用人工核定并标来源，不杜撰第五条之外的价目。
3. **Given** 原创任务且无适用规则，**When** 完成，**Then** 成果可归档，工时走明确人工登记待核定，不套未授权规则。
4. **Given** 管理员代审，**When** 通过，**Then** 管理员不获得部长审核工时。

### User Story 4 - 工作登记与规则管理 (Priority: P2)
一件一条登记：干事只本人、部长本部、管理员全部；周次、内容、类型、工时、备注、附件；有规则自动带出，其他手填且标人工。
**Why this priority**: 现实例外必须能进入期末账。
**Independent Test**: 手填2.5h、部长有理由核定为3h，原值和记录保留。
**Acceptance Scenarios**:
1. **Given** 空、零或负工时，**When** 提交，**Then** 拒绝；其他类型必须手填。
2. **Given** 规则管理，**When** 管理员更新费率或加急参数，**Then** 历史工时不变，未来记录引用新版本。
3. **Given** 审核基础规则，**When** 改默认2h，**Then** 拒绝；已授权的具体条目例外核定仍可做。

### User Story 5 - 排班、提醒与异常关闭 (Priority: P2)
排班给部长建议并由部长确认；每单提醒提前量可配，临期与逾期各一次给当前责任人。离任导致任务无法正常完成时强制归档。
**Why this priority**: 自动化同时保持责任清晰。
**Independent Test**: 同一提醒调度重跑不会再写第二条；强制关闭不产生工时。
**Acceptance Scenarios**:
1. **Given** 待派/执行/审核，**When** 提醒触发，**Then** 分别发部长/干事/当前审核人，通知不重复。
2. **Given** 强制关闭，**When** 部长或管理员输入理由，**Then** 明确“工时未自动核算”，不生成虚假账目，保留历史。
3. **Given** 非管理员，**When** 尝试重置/改规则，**Then** 拒绝；生产重置必须独立确认不可默认暴露。

### Edge Cases
同名稿不同网站、多人创作的分配、成员离任、跨部成员、管理员代办无工时、重复任务与重复归档、通知失败重试、历史规则快照、报名截止、封存后补账。

## Requirements *(mandatory)*

### Functional Requirements
- **FR-201**: 实现全部六部门及本部操作范围，办公统计跨部能力独立于教师审批。
- **FR-202**: 实现采编→办公逐篇挂网、原创/转载计价、附件与验收、关联排版。
- **FR-203**: 实现摄制预约、派发、原子抢单、完成验收、48h独立加急快照。
- **FR-204**: 六部通用需求、美编三档与原创人工登记都能交付自动归档。
- **FR-205**: 按基准§4原样建立24条有效规则，列明来源、单位和有效期；原创为0条而非猜价。
- **FR-206**: 使用1/10000小时与金额分；默认10元/h，严格区分摄影预约与排版报名加急；倍数作用于创作工时。
- **FR-207**: 工作登记每件一条，自动规则与人工区分，审批核定及历史审计。
- **FR-208**: 状态由事件推导；退回理由必填且原承接人重做。
- **FR-209**: 两种提醒各至多一次，面向当前责任人，可靠通知出站及失败重试。
- **FR-210**: 强制归档不生成自动工时，管理员参数修改版本化并审计。
- **FR-211**: 沿用001报表视图、封存、档案与共用小程序接口。
- **FR-212**: 摄制12元/每件2h、采编内容审校、轮值、美编复杂审核等未定细节保持决策来源，生产计发前确认或明确人工核定。

### Key Entities
001公共实体 + 稿件挂网明细/网站、预约、抢单、设计复杂度、轮值、规则版本、工作登记、提醒执行、强制归档理由。

## Success Criteria *(mandatory)*

### Measurable Outcomes
- **SC-201**: 挂网两稿、摄制普通/加急、美编三档、六部门需求与人工登记均有独立验收。
- **SC-202**: 24条基础规则与基准逐项一致，教师/外部/管理员代审不误计。
- **SC-203**: 抢单竞态仅一人成功，重复完成与提醒重跑不重复。
- **SC-204**: 强制归档0条自动工时，历史规则和封存金额不受新配置影响。
