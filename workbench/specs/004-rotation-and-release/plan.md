# 实施规划

技术环境沿用 React、Express、PostgreSQL、PGlite、ExcelJS、微信小程序和 CloudBase。工时政策和权限遵循章程。迁移为增量，旧时段数据保留，封存和归档语义保持一致。

先实现 Web 与迁移并验证，再打包和核验公开访问，最后修改现有小程序。上线资料和旧数据分别核对。详见 research.md、data-model.md、contracts/api.md 和 quickstart.md。

## 2026-11-26 接入修订

按用户要求及真实隔离验证，采用 CloudBase PG HTTPS/RPC。云托管继续运行 React 和 Express，文件转入 PG 模式私有云存储。pg/PGlite 回调事务不能直接拆为多个 HTTP 请求；新增命名仓储和单次数据库业务函数，覆盖账号、六部门、归档、工时、报表和配置等全部路径。

章程检查：保持关系模型、服务端权限、正常完成/归档/一次计时的同事务语义、调整审计、封存不可变和旧库只读核对边界。Key 仅注入后端，私有 schema 与入口限制调用；函数按有效会话解析当前权限。

实施修订：复用原服务端业务逻辑，在一次性内存 SQL 工作副本执行，通过捕获行变更 + revision 比较将每个完整业务命令提交到单次云 RPC。权威数据始终在云端关系表；工作副本不可离线写入，也不作为生产持久化数据库。固定 RPC 不接受 SQL。全局版本冲突重跑整个业务函数，服务端会话在云提交内复验。详见 contracts/cloud-http.md；此方式替代逐个重写 PL/pgSQL 业务规则，避免六部门业务漂移。

验收数据实施：独立显式命令先备份，再在临时 SQL 副本中调用现有业务函数生成样例，经约束和业务检查后按外键顺序将增量一次提交云端。使用固定数据集标识判重；不删除已有业务，不改已有账号密码。附件经私有存储上传/确认；测试密码存入忽略的本机文件。公开 API 和浏览器验证后保留样例。精确历史迁移任务与本次验收造数分开。
