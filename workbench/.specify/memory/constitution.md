# 青年传媒中心 Constitution

## Core Principles

### I. 业务基准与决定留痕
MUST 以 `背景文件/BIZ-RULES-FULL.md` 为长期基准，会话明确的新决定优先，并记录覆盖关系。旧代码是参考，不是需求权威。未决计价不能当作已确定政策。

### II. 共用关系数据与服务端权限
MUST 让两端共用业务接口；任务、版本、审核、成员、工时分别建模并关联。MUST 在服务端验证身份、部门、当前环节与版本，不接受客户端自报角色。教师审核和系统管理权限分开。

### III. 自动归档与一次计发
MUST 在满足完成条件后自动归档成果、版本、审核历史。完成、归档、工时生成必须在同一事务执行，以唯一约束防重复计发。强制关闭不得伪造工时。

### IV. 内部成员工时可核对
MUST 不给教师和外部人员计发工时。每项贡献一条记录，规则值和核定值分开，调整保留前后值、原因、时间、操作人。MUST 用整数小时单位与分金额，封存保存快照。

### V. 增量与真实验证
MUST 按规格、规划、任务、分析、实施推进；验证权限、版本、事务、重试和报表封存。MUST 区分本地验证、云联调、未接入服务，不用模拟结果冒充真实联调。

## Product Boundaries
Web 负责调度、审校、档案、报表；小程序负责快捷需求、进度、材料和轻量处理。群消息通过可替换接入发送；未接通时保留真实状态。

## Development Workflow
全量规则写入业务覆盖表，按闭环实施。数据库变更提供迁移。开发数据与旧程序生产数据隔离；任务完成勾选并记录实测结果。

## Governance
用户新决定优先并须落到规格。原则意义变动升主版本，新增原则升次版本，文字修正升修订版本。功能实施前检查遵守情况。
