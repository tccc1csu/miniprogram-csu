# 软件需求规格说明书（SRS）框架

版本：0.1-draft  
系统：青年传媒中心工作统计与协作小程序  
基线：`miniprogram-1` 云开发版本  
状态：待评审

## 1 引言

### 1.1 编写目的

定义青年传媒中心在人员、部门、工作量、跨部门协作和日常信息共享方面的业务需求，为系统实现、测试、课程展示和后续迭代提供统一依据。

### 1.2 项目背景与问题

- 工作量、工时和津贴容易分散在群聊、表格和人工统计中。
- 部长需要按周维护本部门成员记录，管理员需要跨部门汇总和核算。
- 采编、办公、摄制之间存在任务交接，但状态、责任人和截止时间需要可追踪。
- 通讯录、建议、投票和通知缺少统一入口。

### 1.3 产品范围

**当前范围**：账号与角色、部门与人员、任务明细、每周汇总工作量、统计与周报、采编办公协同、摄制预约、通讯录、活动建议与投票、活动通知、会议确定的工时/时薪规则、任务提醒。

**明确不在当前范围**：完整企业 OA、财务报销、考勤打卡、客户 CRM、通用审批引擎、即时聊天和复杂项目甘特图。它们可作为未来候选能力，但不应因参考 OPMS 而自动纳入。

### 1.4 术语、缩略语和参考资料

| 术语 | 定义 |
| --- | --- |
| 管理员 | 维护全中心配置、人员、规则并审核协作结果的角色 |
| 部长 | 负责本部门人员和工作量维护的角色 |
| 成员 | 查看个人记录、参与协作、提交建议或预约的角色 |
| 任务明细 | 某一项已完成或已归档任务产生的成员、任务类型、工时、来源和归档信息 |
| 周汇总记录 | 某成员某周所有任务明细及允许的人工补录明细的汇总结果 |
| 协同流转 | 需求发起、派发、执行、反馈、审核、归档的业务过程 |
| DDL | 任务或预约的截止时间 |
| SRS/SDD/STD | 软件需求规格说明书/软件设计描述/软件测试文档 |

参考：本项目 README 与源码；KADA Cooperative System 的 SRS/SDD/STD；OPMS README 和路由/模型结构；IEEE 830、1016、829 的课程化简化实践。

## 3 系统功能需求

### 3.1 认证与账号（AUTH）

| 编号 | 需求 | 优先级 | 验收摘要 |
| --- | --- | --- | --- |
| FR-AUTH-001 | 支持微信授权登录和姓名密码登录 | Must | 已绑定账号可授权进入；密码登录可切换测试/正式账号 |
| FR-AUTH-002 | 支持注册、部门和角色绑定 | Must | 注册校验重名、角色和部门合法性 |
| FR-AUTH-003 | 基于会话 token 鉴权并支持过期处理 | Must | 未登录或过期请求被拒绝 |
| FR-AUTH-004 | 用户可注销账号，管理员可管理用户角色 | Should | 注销和角色变更有明确确认及权限限制 |

### 3.2 组织与人员（ORG）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-ORG-001 | 管理部门、成员、用户账号 | Must |
| FR-ORG-002 | 成员与账号、部门之间保持可追踪关联 | Must |
| FR-ORG-003 | 提供按部门、姓名和角色查询 | Should |

### 3.3 工作量与津贴（REC）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-REC-001 | 每项已完成或已归档任务形成一条可追踪的工作明细 | Must |
| FR-REC-002 | 系统按成员和周次汇总任务明细，形成一条周汇总记录 | Must |
| FR-REC-003 | 成员或部长可在允许范围内补录、修订人工工作明细 | Must |
| FR-REC-004 | 同一任务来源不得重复生成工作明细，周汇总可重复计算但结果一致 | Must |
| FR-REC-005 | 管理员和部长可按部门、成员、周次查看明细与汇总 | Must |
| FR-REC-006 | 系统按会议确定、由开发者维护的规则计算津贴并支持周报文本和 CSV 导出 | Must |

## 5 非功能需求

| 编号 | 类别 | 初版指标 |
| --- | --- | --- |
| NFR-SEC-001 | 安全 | 所有业务云函数校验会话和角色权限；数据库不由小程序直接读写 |
| NFR-SEC-002 | 隐私 | 密码不明文展示；成员只能看到授权范围内的个人或流程数据 |
| NFR-PERF-001 | 性能 | 常用列表和统计请求在正常演示数据量下 2 秒内返回 |
| NFR-REL-001 | 可靠性 | 关键状态变更具备幂等性，重复提交不产生重复记录 |
| NFR-USE-001 | 易用性 | 部长批量录入、成员提交和管理员审核均可在移动端完成 |
| NFR-MAINT-001 | 可维护性 | 前端通过统一 `utils/db.js` 调用接口，业务权限集中在云函数 |
| NFR-PORT-001 | 可移植性 | 支持微信开发者工具和真实微信环境；演示数据与正式数据可区分 |

## 6 业务规则与约束

- 每项任务都形成明细记录；系统按成员和周次把任务明细汇总为一条周汇总记录。
- 工时、时薪、加急倍率和流程职责由会议确定，开发者负责维护规则配置并记录版本；管理员使用规则进行审核和统计。
- 采编协同必须按“待办公部派发→待干事同步→待管理员审核→已归档”迁移；摄制预约必须按“待摄制部派发→待摄制干事完成→待办公部归档→已归档”迁移。
- 测试账号和演示数据只能在测试阶段启用，正式环境必须关闭或隔离。
- 小程序端不直接访问云数据库，所有权限判断在云函数完成。
- 自动归档和自动计工时必须具备幂等性；重复回调不能重复生成任务明细。
