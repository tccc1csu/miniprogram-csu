# 2026-10-09 业务说明审阅记录

本记录用于解释本轮修订，不作为课程作业正文。两张手写说明用于识别组织职责，两张小程序截图用于核对专门流程；截图中的流程说明不等于已经完成端到端运行验证。本轮只修改课程文档。

## 1. 组织与职责摘要

| 人员或部门 | 从说明中确认的职责 |
| --- | --- |
| 小程序管理员 | 维护小程序及组织人员信息；技术维护身份不能自动等同于指导老师的稿件审核职责 |
| 各部门部长团（简称部长） | 派发任务，可依据排班表安排任务；运营部部长另外承担推文一审 |
| 各部门干事（账号角色为普通成员） | 完成本部门任务；手写图未另作说明的部门工作由干事执行 |
| 外部门人员 | 向运营部提出推文转发需求、向摄制部提出拍摄需求、向办公部提供需挂网稿件；是业务服务对象 |
| 指导老师 | 对所有稿件二审，审查内容、表述及政治性；截图中通过管理员账号完成采编协同审核 |
| 办公部 | 接收采编部和外部门稿件并挂网；承担津贴统计；指定成员负责摄制归档；用户进一步确认由办公部部长生成／导出中心周报 |
| 摄制部 | 完成拍摄或制作；除派发外还需要先到先得的抢单机制 |
| 采编部 | 为办公部挂网、运营部推文供稿；手写图也提及稿件审核，具体一审岗位未明确 |
| 运营部 | 转发外部门推文，也自行写稿制作推文；部长一审，老师二审 |
| 美编部 | 接受各部长及各类人员提出的绘画／设计需求 |
| 原创部 | 基本职能与运营部相近，相对自足；名称也与现有部门常量一致；不据此推定其审核岗位与运营部完全相同 |

## 2. 两条截图流程

1. 采编部报备 → 办公部部长派发 → 办公部干事同步 → 指导老师审核 → 自动归档。登记标题、稿件名称、原创／转载类型、投稿平台；截止日期可选。审核通过后核算原创采编贡献和办公同步贡献，不能把转载任务算作原创稿件贡献。
2. 中心任何成员预约 → 摄制部部长派发 → 摄制干事提交成果并指定办公归档成员 → 指定办公成员归档。归档后分别形成摄制与归档工时，导出周报时结合部门时薪计算津贴。归档成员可沿用上次选择，但每次必须确认有效责任人。

## 3. 对旧作业的纠正

- 业务范围覆盖六个部门，不能只剩下采编和摄制两条线；外部门是需求来源，不是内部第七个业务部门。
- 增加推文制作／转发、美编服务的业务用例，用通用分阶段任务表达其他跨部门合作；不为每一个内部动作单独造业务用例。
- 保持三个账号角色，结合部门与职责解释权限；一项流转任务可经过多个部门，但每一阶段只有一个当前负责人。
- 中心周报的主要执行者改为办公部部长。管理员的维护权与老师的审核职责分别说明。
- 增补抢单、运营部推文一审、稿件二审和通用任务流转规约。通用流程是本轮拟开发建模方案，不声明已上线。
- 序列图中接收箭头的一方执行消息动词；继续采用课程的人／非人图例。图中系统是业务实体。
- 保留访谈的人工协同作为现状基线，并注明采集时期；不把现有小程序截图伪装成人工现状。

## 4. 尚需细化的事实

- 外部门是否有登录账号，还是由中心成员代为登记；业务服务对象身份不直接推出软件登录权。
- 非指导老师的维护管理员是否也获授权审核。
- 采编稿件一审的岗位、原创部审核安排，以及一审与截图中“同步后老师审核”之间的具体衔接。尚未确认的审批节点不补画进现状图。
- 通用流转任务由谁创建、谁确认各阶段完成、最终如何认定可计工时；本轮提出“发起成员编排、部门部长派发和确认、按已确认贡献归集”的建模方案，不能视作会议已决定的制度。
- 摄制抢单开放时机和派发／抢单的切换责任。文档以“已开放、未被承接的摄制任务”为抢单前提，不假定所有预约都可抢。
- 加急的 2 天按 48 小时还是自然日、冲突对应的资源范围、1.5 倍率适用的贡献范围，继续等待业务细化。
