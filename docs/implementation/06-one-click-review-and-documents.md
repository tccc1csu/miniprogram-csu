# 2026-10-14 一键审核、业务附件与计量口径

本次以实际小程序的可用流程为基础，采用课程中的成果、审核结论、贡献依据及计量快照概念。代码基线为 `19c55e0`，分支为 `refactor/course-runtime-alignment`。本地导出只读检查与内存重放均未连接云环境，原始备份不进入 Git。

## 已确认的业务决定

- 审核通过只需一次操作，不要求填写意见；服务端依据登录账号记录实际操作人、审核时间、通过结论和默认意见。退回修改为独立操作，可提交修改意见和接收人。
- 公众号排版在布置时指定一审、二审人员。两岗用于记录人员和归集审核贡献；部长或现有授权管理员一次确认后归档，不等待两人分别操作，也不生成两条虚构的通过记录。
- 每项自动归档审核贡献合计 **2 小时**，按不重复的成员 ID 平分。同一人兼任两岗获得 2 小时，两人各 1 小时；三人按万分之一小时分配余数，确保总数仍为 2 小时。
- 摄制工作沿用已配置工时及任务保存的加急倍率；摄制归档审核按合计 2 小时计算，不再乘加急倍率。公众号加急仍为提醒，不增加排版工时倍率。
- 任务明细与成员周汇总并存。同一来源、贡献类型、成员只生成一次贡献；不同贡献类型分别保存，累计到同一周汇总。

| 业务 | 本次处理 |

| 部门与跨部门项目 | 项目材料、各部门各阶段成果可上传；保留阶段成果历史；并发完成部门任务不会相互覆盖 |

目前排版人员选择范围沿用运营部成员。通用项目阶段没有已确认的独立计费政策，本次不凭部门阶段完成自动新增工时。公共文档库已有上传入口，业务附件不混入公共文档库列表。

## 与课程概念和字段的对应

| 课程概念 | 现行云数据库承载 | 关键字段及含义 |
| --- | --- | --- |
| 审核岗位安排 | `handoffs.reviewAssignments` | `stage` 为岗位序号；`member_id` 为贡献成员；不是该成员实际审核凭证 |
| 审核结论 | `handoffs.approval_records`，活动建议同名数组 | `reviewer_id`、`decision`（PASS／RETURN）、`opinion`、`reviewed_at`；增加 `reviewer_user_id` 保存实际账号 |
| 提交成果 | `handoffs.outcome_submissions` | `outcome_id`、`submitted_by`、`submitted_by_user_id`、`submitted_at`、`content`、`attachments`；审核关联本次成果 |
| 文档附件 | `files` 登记及业务引用 | `fileID` 为兼容云存储引用；业务引用保存真实上传人和登记时间，不保存临时本地路径 |
| 工作贡献 | `contribution_basis` | `source_id`、`type_id`、`member_id`、`department_id`、`evidence`、`evidence_attachments` |
| 贡献计量 | `contribution_measurement` | `basis_id`、`policy_id`、`base_hours_u`、`assessed_by`、`assessed_at` |
| 计量政策快照 | `contribution_policy` | 工时及倍率快照；审核保存 `total_hours_u=20000` 和实际分摊人数 |
| 部门时薪快照 | `allowance_standard` | `department_id`、`hourly_rate_cents`、`captured_at` |
| 周汇总 | `weekly_records` | 保留原接口字段与旧 ID；自动贡献事务更新汇总；导出不重复计量 |

操作人没有计量成员资料时（例如维护管理员），`reviewer_id` 为空，仍以真实账号保存审核记录。旧任务无指定审核贡献人时标记待核对，不凭空建立成员或计发审核工时。

关系型参考设计的 55 张表表达课程完整目标模型，CloudBase 当前使用集合与嵌套记录，不能宣称已物理实现全部表或 3NF。课程稿件同版一审、二审描述的是完整稿件审查目标，**不等于本次排版排班中的两次系统审批**；本次确认对排版模块适用。既有课程图保留目标范围，实际实现以本文件和测试为准。

## 附件与历史兼容

每次提交最多 10 个附件，单文件最多 50 MB。支持常用文档、表格、演示文稿、图片、压缩包及 MP4。文件先由服务端预登记，再上传并确认云文件存在；服务端核验上传账号和路径，业务引用不信任客户端姓名或时间。微信可预览的文档与图片提供查看入口，其他格式的预览取决于微信能力。

上传中阻止提前提交或关闭所属表单；部分上传失败保留此前成功附件，可继续重试。移除附件仅解除引用，避免直接删掉已归档依据。新提交和真实审核追加历史；旧记录不补造提交时间、审核结果或计量快照。

新审核来源改用成员 ID，同时识别旧 `任务:review`、`任务:review:岗位序号`、`任务:archive` 来源。已统计历史不按 2 小时重算，也不在新版再次累计。新规则按有效业务口径读取，历史快照保留原值。
