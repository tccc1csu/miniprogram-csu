# OPMS 功能参考清单

这是一份“思考清单”，不是本项目的需求承诺。OPMS 是面向企业的 PMS + OA 系统，包含项目、任务、审批、知识、考勤和办公管理等大量能力。以下只挑选与青年传媒中心的组织协作和内容生产场景可能相关的部分，并给出改造方向。

## 1 候选功能总表

| OPMS 能力 | 对本项目的潜在价值 | 建议决策 | 适配方式/边界 |
| --- | --- | --- | --- |
| 项目/需求/任务 | 把采编、活动、摄制从一次性协同扩展为可跟踪任务 | 建议优先评估 | 先扩展现有 `handoffs`，不要立即新建完整 PMS |
| 任务看板 | 直观看到待派发、进行中、待审核、已归档 | 建议引入 | 用现有状态做轻量看板 |
| 日历视图 | 查看预约、DDL、活动和通知 | 建议引入 | 统一读取预约、协同和活动日期 |
| 甘特图 | 适合长期大型活动的时间依赖 | 暂缓 | 当前流程短、移动端复杂度和收益不匹配 |
| 任务/项目报表 | 比单纯周工时更能解释工作进展 | 建议评估 | 增加完成率、逾期率、部门负载指标 |
| 需求/任务附件与文档 | 保存稿件、脚本、拍摄结果和证明材料 | 建议评估 | 先用云存储 + 权限控制，明确文件生命周期 |
| 知识库 | 沉淀拍摄规范、投稿模板、部门流程 | 建议优先评估 | 轻量分类、搜索、收藏和版本，不做开放社区 |
| 公告/消息 | 集中发布活动、截止时间和制度 | 已部分覆盖/可增强 | 对接现有 notifications，增加已读和定向部门 |
| IM 即时聊天 | 任务上下文沟通 | 暂缓 | 微信群已承担即时沟通，先做评论/反馈记录 |
| 日报/周报/月报 | 规范工作复盘和部长审核 | 建议引入 | 与 weekly_records 区分：报告是叙述，记录是核算 |
| 考勤/打卡 | 了解值班、活动出勤 | 暂缓 | 非当前核心目标，涉及隐私和规则争议 |
| 请假审批 | 处理部门排班和活动冲突 | 可选 | 只有确认真实业务需求后再做通用审批 |
| 出差/外出 | 摄制外出安排 | 暂缓 | 先在摄制预约中记录地点、时间、联系人 |
| 加班申请 | 与加急、工时补录相关 | 可选 | 不与自动归档工时重复计算 |
| 费用报销/办公用品 | 活动成本管理 | 暂缓 | 需要财务流程和凭证合规，不宜顺带开发 |
| 组织/岗位/权限组 | 更细的协作权限 | 建议引入 | 先保留管理员/部长/成员，未来加流程责任人权限 |
| 人员简历 | 通讯录之外的能力档案 | 可选 | 可先增加技能标签和擅长方向 |
| 相册/活动作品 | 展示和复盘活动成果 | 建议评估 | 与摄制结果、通讯录分开设计，先做活动相册原型 |
| 评论/点赞 | 促进建议和知识反馈 | 已部分覆盖/可增强 | 建议只用于建议/知识，不给工作量数据增加社交噪音 |

## 2 建议优先级

### P0：适合近期课程案例迭代

- 协同任务看板：复用已有状态和责任人。
- 统一日历：聚合摄制预约、协同 DDL、活动投票结束时间。
- 工作报告：日报/周报叙述与工时记录分离，并支持部长审核。
- 权限组扩展：把“流程关联部门”和“可操作动作”明确化。

### P1：有明确业务需求后加入

- 轻量知识库：制度、模板、经验和常见问题。
- 活动/作品相册：与摄制预约结果关联。
- 附件与版本：稿件、脚本、成片链接和审核记录。
- 逾期与负载报表：为管理员提供过程指标。

### P2：暂不纳入主线

- 甘特图、完整 CRM、考勤打卡、费用报销、办公用品、即时聊天。

## 3 功能决策卡模板

每个候选功能在进入 SRS 前填写：

| 项目 | 内容 |
| --- | --- |
| 功能名称 | 例如：协同任务看板 |
| 解决的问题 | 当前流程中的具体痛点 |
| 使用角色 | 管理员/部长/成员 |
| 与现有模块关系 | 复用或新增的实体、页面、接口 |
| 最小可交付版本 | 一次迭代能完成的范围 |
| 数据影响 | 新集合/字段/索引/迁移 |
| 权限风险 | 是否产生越权或敏感数据问题 |
| 验收指标 | 可观察、可测试的结果 |
| 决策 | 保留/改造/暂缓/拒绝 |

## 4 参考边界

- OPMS 的“项目、任务、需求、测试、文档、版本”是企业项目管理模型；本项目应围绕“内容生产、部门协作和工时核算”重命名和裁剪。
- OPMS 的“请假、报销、出差、加班、考勤”不能仅因为存在路由就直接移植；它们需要新的业务规则、审批责任和隐私设计。
- OPMS 的“权限组”值得借鉴其权限建模思想，但当前系统应先保证三角色模型稳定，再逐步细化到流程责任人。
- 参考项目的页面、数据库字段和代码不作为本项目实现依据；本清单只记录可借鉴的产品问题和设计方向。
